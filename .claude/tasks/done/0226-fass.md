# A collection of formula examples

I'm thinking about creating a formula as a service SaaS. An elo formula would
be easy to publish and execute as a webservice. That's not the scope of this
task though : here we just want to list examples for formula that would be
published there.

## Problem to solve

Find lots of real world small formula examples where

- Each is representable by a rather simple/short Elo program
- Each has a rather simple input schema that would easily convert to an input form with various fields
- Each provides an interesting output
- Each can come with nice tests/examples as a case table

## Examples I have in mind

- EU TAX number validation
- %97 back account validator
- Small pricing / discount engine
- Whether a year is a bisectile one
- etc.

## Remarks

- If the formula is a great example but cannot be implemented in Elo, you may
propose language & stdlib improvements (as well as bug fixes of course).
- Let's build those examples as .elo and .test.elo files, where the later is
an Elo program importing the former and showing the case table in a nice,
executable way

## What was built

Thirteen formulas in `examples/formulas/`, each a module declaring `Input` and
exporting `formula`, each with a `.test.elo` whose value *is* its case table and
whose `check` makes a wrong row a failure. `test/acceptance/test-formulas.sh`
type-checks and runs all thirteen on JavaScript, Ruby and Python (39 runs), and
`test-all.sh` calls it. Conventions, the host's two-line call and the two
limits (no SQL, `--strict`) are in `examples/formulas/README.md`.

> **The layout moved on.** 0233 turned each formula into a *bundle* — a
> directory of five files — and the `.test.elo` convention described above is
> gone; its cases are `cases.elo`. The thirteen formulas themselves are

Writing them found four portability bugs, each fixed first, in its own commit,
after being seen red on the targets it broke:

- `0227` — `Int('08')` was octal on Ruby; `Int('12abc')` was `12` on JavaScript
  (including in schema coercion); a dynamic `Int(3.7)` was refused there
- `0228` — `split(s, '')` raised on Python and answered the whole string on
  PostgreSQL, which is the only way Elo has to walk a string
- `0229` — an `if` used as an operand was mis-emitted on three targets:
  `1 + (if false then 10 else 20)` was `20`, or a `TypeError`
- `0231` — a string function lost the parentheses around an expression
  receiver: `startsWith('ab' + 'cd', …)` raised on Python, and
  `contains(a + 'cd', x)` with an untyped `x` answered `"abfalse"` on JavaScript

And two write-ups rather than fixes: `analyzed/0230` (a Date lives in the
machine's time zone on JavaScript, so days between two dates are off by an hour
across a DST change — the fix is a decision about what zone the target runs in)
and `ideation/0232` (what the catalogue asked the language for and did not get:
a weekday, an index in `map`/`reduce`, a non-raising coercion).
