elo-form: six ways to put a form in a page

The same schema, the same form, delivered six ways. They differ in what the browser has to load, what a Content-Security-Policy has to allow, and above all in where the schema's code runs: the question that matters when the person who wrote the schema is not the person filling the form in.

Every page here is served by demo/server.mjs, a single file with no dependency beyond elo-form's own, written to be copied from. Each page sends real requests (open the network panel) and carries its own policy as a response header. The schema is demo/order.elo: edit it and reload.

In every mode the labels, hints and error texts come from the schema: whoever wrote it decides what the form says. And in every mode the browser's verdict is a courtesy: the server runs raw |> Type again on whatever it receives (check() in the server).

What the server does, in four functions

  1. plan(): reads the schema into the form as JSON. It parses; nothing of the schema is run. /order/plan.json
  2. checksModule(): compiles Elo's checks into a JavaScript module for a page to load. /order/checks.js
  3. check(raw): the verdict that counts, raw |> Order. POST /order/check
  4. htmlForm(posted): writes the form as HTML, and reads it back when it is sent. /4-html

For mode 6 it also serves the worker's script, /lib/elo-form.worker.js, with a policy header of its own: the one line that keeps the schema's code off the network.
