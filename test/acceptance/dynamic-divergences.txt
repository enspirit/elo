# Fixtures the force-dynamic axis cannot run yet, and why.
#
# `ELO_FORCE_DYNAMIC=1` recompiles the corpus with every call dispatched as
# though no operand type were known — the opposite end of the axis from
# `--optimize`. The two must answer the same, and these are the places where
# they do not. Each line is a to-do, not an allowance: the list should shrink
# to nothing.
#
# A divergence is marked REAL when it reproduces in ordinary Elo with a lambda
# (a lambda parameter is typed `any`, so a real program can reach it), and
# FORCED when only the all-`any` compilation reaches it. A FORCED one is not
# therefore harmless — it is an `any` implementation nobody has ever run, which
# is exactly what `dispatch-coverage` lists — but it is not reachable from
# source today, so it is the weaker of the two.
#
# Format: one fixture basename per line.
#
# **The list is empty.** Every entry 0248 inherited is closed:
#
#  * `type-selectors` and `datapath` were the two REAL ones — String(x)
#    returning the display form, and fetch(d, p) raising a host TypeError on an
#    object path. Both fixed, with `reference/string-conversion-dynamic.elo`
#    and `reference/datapath-dynamic.elo` asserting the typed and dynamic
#    forms agree.
#  * `interval-arithmetic`, `concat`, `typeOf-arithmetic` and
#    `temporal-duration` were listed as FORCED, and all four turned out to
#    reproduce with a lambda once characterised. They are
#    `reference/dynamic-arith-dispatch.elo` now.
#  * `temporal-startof-endof` and `dynamic-ambiguous-dispatch` were the
#    timezone bug, fixed by 0240.
#
# Keep it empty. A line added here is a bug that is being carried, so it needs
# the REAL/FORCED verdict and a sentence saying what the two paths answer.
